# 裁定原则库（成文法）

> 人工策展的可推广裁定规则。每条 `## PID: 标题` 一段，下面用固定 bullet：
>   - stmt:    可推广的规则
>   - why:     缘由（帮模型迁移到无 FAQ 的组合）
>   - applies: 何时套用
>   - src:     权威来源（**必填**，错一条污染大）
>   - 正例/反例: 帮模型对齐
> 加原则就追加一个 `##` 段，编号续接。多正例/反例可多行续写。

## P01: cost 与效果的区分
- stmt: 发动所支付的 cost 不视为「效果」处理。以「被效果…」为触发条件的效果，不会因支付 cost 而触发。
- why: cost 发生在效果处理之前，不进入效果处理流程。
- applies: 问"X 的丢弃/送墓会触发 Y 吗"且 X 的动作在"才能发动"前（即 cost）。
- src: OCG 官方裁定 / PSCT 统一原则（90X 后）
- 正例: 魔力净化——"丢弃1张手卡才能发动"，丢弃是 cost，不触发"被效果丢弃去墓地"。
- 反例: 刻魔的咏圣——丢弃在效果处理时（"才能发动"后），是效果，会触发"被效果丢弃去墓地"。

## P02: 触发条件字面性
- stmt: 以「被X去墓地」为触发条件的效果，只有 X 字面发生才触发。「丢弃」≠「送去墓地」≠「作为cost」。
- why: PSCT 对动作措辞有严格区分，措辞不同即机制不同。
- applies: 涉及暗黑界/手札断杀等"被效果丢弃"触发 vs"送去墓地"措辞的组合。
- src: OCG 官方裁定
- 正例: 手札断杀的"送去墓地"不满足"被效果丢弃"触发（暗黑界系列不触发）。
- 反例: 强制接收等明确"丢弃"措辞的卡满足"被效果丢弃"。
