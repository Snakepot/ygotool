# ygotool：解决的问题与标准流程

> 一句话：把游戏王效果文本从**自然语言**变成**可校验结构**，让"查卡"与"裁定问答"可量化验证。
> 配套：`docs/技术路线.md`（为什么这么选）、`.claude/skills/ygotool/SKILL.md`（踩坑 31 条）。
> 本文只讲两件事：① 这个项目到底解决了哪些问题；② 已有流程（SOP）与工具清单。

---

## 一、问题地图

项目从"子串检索 + 直接问 LLM"演进到"工具增强的 ReAct + PSCT 结构化检索 + 评测闭环"，核心是解决 4 类问题：

### 1. 按效果找卡：子串检索答不了

| 项 | 内容 |
|---|---|
| 现象 | 问「从卡组把1只3星怪兽送去墓地」返回 42 张噪声；问「从卡组特殊召唤某卡」把限制句/自肃句也当命中；用户粘贴原文（「把自己的手卡·场上1只怪兽解放才能发动」）找不到卡 |
| 根因 | 动作、来源、目标混在一句且顺序不定；cost 段与效果体无区分；来源区（手卡/卡组/墓地）离动词 9–23 字，窗口匹配不到；「从X特殊召唤的…」这类定语被误当来源 |
| 对策 | `ygocdb/effect_parser.py`：按 PSCT 剥离「才能发动」、按连词切**动作单元**、单元内绑定 动作/来源/目标、否定句跳过（仅保留 cannot_activate）、剔除修饰语（`_SRC_MODIFIER_RE`）；`ygocdb/ontology.py`：14 类动作 + `map_phrase_to_actions`；`agent/tools.py`：`_render_list` 三档分级（★精确/◆次精确/通用）+ 名单 ≤60 张全量渲染 + 片段一律给原文分句 |
| 证据 | `examples/05`：动作检索 vs 子串检索（901 vs 420；483 vs 1409；88 vs 11180）；误召 42 → 6 张 |

### 2. 裁定问答：模型会编

| 项 | 内容 |
|---|---|
| 现象 | LLM 凭记忆答「某卡可以加入手卡或特殊召唤」，效果原文根本没有 |
| 根因 | 卡牌信息不在模型权重里，必须取数；且回答要可追溯（来源标注） |
| 对策 | 工具增强（答事实必经工具取数）；grounding 约束（关键动作保留原措辞，不得改写）；原则库 P01/P02（成文法，可演绎）；FAQ RAG（案例法，兜底）；置信度分级（有官方FAQ→直答；无FAQ但可依原则→答并标「中」；都无→明说无依据） |
| 证据 | `eval/result.csv`：7 判例 7/7 裁定一致；must_cite 引用 8–9/9（LLM 方差） |

### 3. 评测：没有断言

| 项 | 内容 |
|---|---|
| 现象 | 改动后只能"问几条看看"，好坏无记录、回归无基线 |
| 根因 | 输出是自然语言结论，传统单元测试断言不了 |
| 对策 | 判例集 `agent/data/cases.jsonl`（问题 + 金标裁定 + must_cite + `fewshot` 标记，评测时 few-shot 置 0 防泄漏）→ `eval/run.py`：LLM-as-judge（严格首行 YES/NO）+ 引用核查 → `eval/result.csv` 逐条给失败原因 |
| 证据 | C28 金标补冰偶镜（judge 从 NO→YES）、C23 宽口径重建、judge 严格化（修 `"不一致" in "一致"` 误判）都是评测驱动的修复 |

### 4. Agent 运行时：ReAct 跑飞 / 空答 / 预算 / 协议

| 现象 | 根因 | 对策（已修） |
|---|---|---|
| 反复调工具，5 分钟以上超时 | 无轮数/调用数上限 | `MAX_ITERS=4` + `MAX_TOOL_CALLS=10` + 轮数耗尽强制无 tools 收尾 |
| 空答案 | thinking 吃满 `max_tokens`，content 没机会生成；`got_content` 跨轮粘滞 | 首轮路由关 thinking、拿到工具结果后开；`got_content` 按轮重置 + 兜底流式 |
| 消息序列非法（API 报协议错） | tool_calls 超限 `break` 后，assistant 里留着无对应 tool 回复的调用 | 超限的 tool_call 补占位 `role="tool"` 消息 |
| 上下文超预算 | 消息序列无裁剪 | `budget.fit_messages` 按**协议块**裁剪（notices → 最旧工具轮 → few-shot/历史 → 最新工具轮硬兜底），tool_calls 与 tool 结果不拆散 |
| `temperature=0.0` 不生效 | `0.0 or 0.2` 走真值判断，0.0 被吞 | 改 `temperature if temperature is not None else …` |
| trace 两条路径字段不一致 | 流式最终 trace 手写 dict，漏 budget/llm_usage；`retrieved_total` 两套语义 | 单一出口 `to_event()`（首尾同形）；`retrieved_total` 统一为裁剪后条数；补 `trace.answer` 累计与 usage 转发 |

> 对应提交：`bb1a886`（预算接入 ReAct）、`caee7b4`（tool_calls 占位）、`5938d7f`（流式 got_content）、`5b0a7b8`（judge 严格）、`683cc68`（trace 统一）、`386e8b8`（temperature）、`d1920d0`（C23 修饰语 + 全量渲染）。

## 二、工具清单（11 个，`agent/tools.py` → `TOOLS`）

| # | 工具 | 用途 | 何时选它 | 要点 |
|---|---|---|---|---|
| 1 | `search_card` | 按卡名模糊查 | "X 是什么卡/查 X" | 一次拿到 id 即可，同一张卡不重复取 |
| 2 | `get_card_detail` | 完整详情 + 官方 FAQ 数量 | 裁定/详解某卡 | 需先知道 id；效果原文用于 grounding |
| 3 | `search_by_action` | 按**动作本体**全量找卡（cost + 效果段都搜） | **带来源/限定条件的找卡首选** | 三档特异度；`reason` 可过滤 cost/effect；`source` 限定来源区 |
| 4 | `search_by_effect` | 效果体结构化复合检索（keyword ∧ source ∧ target） | 明确只查效果体时 | **只搜「才能发动」之后**，会漏 cost 型卡 |
| 5 | `search_effect_phrase` | 按原文片段最长连续匹配找卡 | 用户粘贴/引用效果原文 | 规范化后 ≥4 字连续匹配 + 覆盖率排序 |
| 6 | `search_by_series` | 卡名系列全量 | "X 系列所有卡" | 返回全部不截断 |
| 7 | `rag_search` | 向量检索 FAQ/效果片段 | 裁定找官方 FAQ | embedding-3 跨语言；最多调 2 次 |
| 8 | `decode_card_fields` | YGOPro 位掩码解码（种族/类型/星级/Link/灵摆） | 字段教学/特殊字段查询 | ygocdb 种族编码非标准，表由全量反推 |
| 9 | `get_limits` | 简中禁限表概览 | 构筑/环境 | — |
| 10 | `limit_status` | 单卡禁限状态 | 构筑 | 禁卡/限制/准限/无限制 |
| 11 | `get_release_date` | 各语种首发日期 | 判断是否 90X 前旧措辞卡 | 旧卡措辞含糊须查 FAQ，别从旧文本强推 |

**选工具规则（`agent/prompts.py` REACT_RULE）**：需要卡牌信息先调工具；枚举类（有哪些/列出）只调**一次** `search_by_action`/`search_by_effect`，禁止先猜卡名再逐卡 `get_card_detail`；找卡必须用 `search_by_action`（cost+效果）；phrase 必须带全部限定词；原文→拆 动作+来源(+目标)；查单卡一次到位不重复取；已够信息立即给最终答案。

## 三、标准流程（SOP）

### 流程 A：一次问答（主链路）

```
前端 POST /api/chat（SSE）
  → web/server.py api_chat
  → CardAgent.ask_stream
      ├─ 真模型：_react_stream（原生 function-calling 多轮）
      └─ mock  ：_prepare（确定性管线：正则意图路由 → 工具 → budget.fit → 一次 chat）
  → 每轮：budgeter.fit_messages 裁剪 → llm.stream（tools=TOOLS）
      ├─ tool_calls → ToolRuntime 执行 → 结果以 role="tool" 回灌
      └─ content    → 实时 yield 给前端
  → 收敛/轮数耗尽：强制一次无 tools 收尾
  → trace（首帧 + 终帧同形）+ content + done
  → 前端：Markdown 渲染 / 思考折叠 / 卡牌#id 可点开详情
```

### 流程 B：PSCT 结构化检索（`search_by_action` 内部）

```
phrase → _normalize_query（别名扩写 + 等级N→N星）
  → map_phrase_to_actions（短语 → 动作 key 集合）
  → 遍历全池：tag_action_units(desc)
       parse_clauses（按①分条、剥「才能发动」）
       split_action_segments（按 连词/那之后/或 切动作单元）
       _strip_src_modifiers（剔「从X特殊召唤的」定语）
       match_actions → 绑定 zones（动词前片段；修饰语后重定位）
       否定词跳过（不能/无法/不用/无需…）
  → 过滤：action ∈ keys ∧ reason 匹配 ∧ q_zone ⊆ unit.zones
  → 三档 tier：2=来源一致 / 1=来源更宽 / 0=通用（与限定词档取 min）
  → 排序：tier 降序 → _render_list 渲染（≤60 全量；>60 按 30/15/10 截断 + "其余见左栏"）
```

### 流程 C：上下文预算（`agent/budget.py`）

- **`fit()`（mock 装填）**：优先级 system > 当前问题 > 历史（最新优先）> few-shot > 检索 chunk；超预算先丢低分 chunk、再丢 few-shot，绝不丢 system 与问题；`reserve_completion` 给输出留预算。
- **`fit_messages()`（ReAct 裁剪）**：按**协议块**裁剪，保证 assistant(tool_calls)+全部 tool 回复同进同出；顺序：丢 notices → 丢最旧工具轮（保留最近一轮）→ 丢 few-shot/历史 → 仍超则丢最近一轮（硬保底）。
- 预算报告进 `trace.budget`（Web/CLI 可见），可用 `.env` 或 API 参数覆盖 `max_context`。

### 流程 D：评测回归闭环

```
cases.jsonl（q + golden + must_cite + fewshot）
  → eval/run.py：few-shot 置 0（防泄漏）→ agent.ask → 答案
  → judge_llm 严格 YES/NO（首行白名单）→ 正确性
  → must_cite 核查（卡#id / 原则编号是否出现在答案）
  → eval/result.csv（逐条：判定/理由/引用命中）
  → 失败清单 → 改代码或金标（必须由用户裁定）→ 再跑
```

### 流程 E：数据与索引

```
cards.zip（MD5 增量）→ ygotool refresh → cache/cards.db（14295 卡）
build-index（chunker: card/effect/faq）→ cache/idx_main.db（effect 索引）
build-faq-index（在线逐卡拉 FAQ，0.3s 限流，--resume 断点）→ faq chunk
```

### 流程 F：问题排查

1. 看 trace：工具链 / `iterations` / `llm_usage` / `budget`（Web trace 栏或 CLI 输出）
2. 查 `.claude/skills/ygotool/SKILL.md` 踩坑 31 条
3. 服务侧：改 Python 必须重启（`python cli.py serve` 或 `ygotool.bat`）；只改前端 `Ctrl+F5` 即可
4. 端口清理：`netstat -ano | findstr :8000` 取 PID → `taskkill /F /PID <pid>`

## 五、已知缺口（诚实边界）

- 判例仅 7 条，C01/C02 开卷（答案在 principles.md 正例里）→ 7/7 不代表泛化；判例去开卷扩充是下一步。
- 原则库仅 P01/P02；动作本体覆盖 14 类（含 negate_effect / cannot_activate），仪式/融合/同调/超量/连接/灵摆召唤、覆盖/放置、回收等未覆盖。
- 向量索引为小样例（effect 770 chunk / faq 100 chunk），全量索引是成本项（用户拍板）。
- P06 类"文本提及≠执行"（超再生能力）仍会误召，需句式过滤。
- 无单元测试，靠 trace + 评测 + 31 条踩坑兜底（P2 计划补最小回归测试）。
